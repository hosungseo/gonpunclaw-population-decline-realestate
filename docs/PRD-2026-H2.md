# PRD — 인구감소지역 부동산 근거 기반 탐색기

## 1. 제품 요약

인구감소지역 부동산은 인구감소지역·인구감소관심지역의 법적 특례와 실제 아파트 거래를 함께 보여주는 공공형 안내 서비스다. 이번 버전은 단일 정적 안내 페이지를 총 107개 정책 대상 지역의 지정 근거, 적용 정책, 거래 표본을 지속적으로 갱신·비교할 수 있는 탐색기로 확장한다.

제품의 핵심 약속은 다음과 같다.

> 관심 지역을 선택하면 무엇이 정책적으로 다른지, 실제 거래 표본은 어느 정도인지, 그 판단의 근거와 기준일은 무엇인지 한 화면에서 확인할 수 있다.

## 2. 배경과 문제

현재 제품은 89개 인구감소지역과 18개 인구감소관심지역, 최근 24개월 아파트 거래, 특례 설명, 지도와 비교표를 제공한다. 그러나 거래 데이터가 정적 스냅샷이고, 지역 상세에 고유 주소가 없으며, 정책·법령 설명의 최신 여부를 구조적으로 검증하기 어렵다. 단일 `index.html`에 UI와 로직이 집중되어 있어 갱신과 테스트 비용도 커진다.

해결할 문제는 다섯 가지다.

1. 사용자가 현재 데이터의 수집일과 최신성을 즉시 판단하기 어렵다.
2. 특정 지역 정보만 공유하거나 2~3개 지역을 직접 비교하기 어렵다.
3. 거래 표본이 얇은 지역의 수치가 실제보다 강한 신호처럼 보일 수 있다.
4. 세컨드홈 등 특례의 조건과 시행 시점이 바뀔 때 설명 갱신 누락 위험이 있다.
5. 데이터 갱신과 화면 수정이 수동 작업에 의존한다.

## 3. 제품 원칙

1. **투자 추천이 아니라 근거 탐색이다.** 순위와 매수 신호를 제공하지 않는다.
2. **가격보다 표본을 함께 본다.** 거래량, 무거래 월, 기준기간을 수치와 같은 비중으로 표시한다.
3. **모든 핵심 주장에는 시점과 출처가 있다.** 법령, 고시, 거래 데이터의 기준을 역추적할 수 있어야 한다.
4. **개인별 세무 판단을 확정하지 않는다.** 확인 순서와 공식 근거를 제공한다.
5. **107개 지역을 같은 품질 규칙으로 다룬다.** 데이터가 없다는 사실도 결과다.
6. **정적 배포를 우선한다.** 사전 생성과 JSON 갱신으로 운영비와 장애 지점을 줄인다.

| 지역 활동가·사업자 | 가격 외 지역 맥락은 어디서 보나 | 정책정보와 검증된 현장지도 연결 |

## 6. 핵심 사용자 여정

### 여정 A — 특정 지역 탐색

1. 사용자가 지역명을 검색한다.
2. 검색 결과에서 지정 유형과 시도를 확인한다.
3. 지역 상세에서 지정 근거, 핵심 특례, 최근 24개월 거래 표본을 본다.
4. 데이터 기준일과 원출처를 확인한다.
5. 지역 URL을 복사해 공유한다.

### 여정 B — 지역 비교

1. 사용자가 지도나 표에서 첫 지역을 선택한다.
2. 비교할 지역 1~2개를 추가한다.
3. 거래량, 중위가격, ㎡당 가격, 무거래 월, 지정 유형을 나란히 본다.
4. 표본 경고를 확인하고 비교 URL을 공유한다.

### 여정 C — 세컨드홈 확인

1. 사용자가 세컨드홈 확인 순서를 연다.
2. 기존 주택 수, 대상 지역, 취득 시점, 공시가격 등 확인 항목을 따라간다.
3. 제품은 확정 판정 대신 확인해야 할 조항과 적용 시점을 보여준다.
4. 사용자는 국가법령정보센터와 공식 문의처에서 최종 확인한다.

## 7. 릴리스 범위

| 릴리스 | 목적 | 포함 기능 |

| R1 | 최신 자료라고 믿을 수 있는 사이트 | 갱신 파이프라인, 출처 매니페스트, 구조 분리, 데이터 검증, 기준일 표시 |

## 8. 정보구조

- `/` — 서비스 설명, 핵심 특례, 지역 탐색 진입
- `/regions/` — 107개 지역 검색·필터·지도·표
- `/region/[regionSlug]/` — 지역 상세
- `/compare/?regions=...` — 2~3개 지역 비교
- `/policies/` — 특례별 설명과 근거
- `/policies/second-home/` — 세컨드홈 확인 순서
- `/sources/` — 데이터 출처, 기준일, 방법론, 이용조건
- `/about/` — 목적, 한계, 면책, 문의

정적 호스팅을 유지하기 위해 지역 페이지와 정책 페이지는 빌드 시 생성한다.

## 9. 기능 요구사항

### FR-RE-001 공통 지역 기준정보 — P0

요구사항:

- 107개 지역마다 고유 시군구 코드, 표준 지역명, 시도, 지정 유형, 지정 근거 ID를 가진다.
- 지역명 변경과 행정구역 변경 이력을 처리한다.
- 화면·거래 데이터·지도 경계가 같은 지역 키를 사용한다.
- PolicyMap과 공유 가능한 지역 코드 스키마를 문서화한다.

수용기준:

- 중복 지역 키가 없다.
- 107개 지역 모두 지정 유형과 시도를 가진다.
- 거래 데이터에 없는 지역도 `무거래` 또는 `수집 오류` 상태로 남는다.

### FR-RE-002 월별 거래 데이터 파이프라인 — P0

요구사항:

- 원자료 수집, 정규화, 중복 제거, 지역 연결, 월별 집계, 검증, 산출물 생성을 별도 단계로 실행한다.
- 최근 24개월 창을 기준월에 따라 자동 계산한다.
- 지역별 거래 건수, 거래금액 중위값, ㎡당 중위값, 최저·최고값, 최근 거래월, 무거래 월 수를 산출한다.
- 취소 거래와 중복 레코드 처리 규칙을 문서화한다.
- 원자료 API 장애 시 기존 검증본을 유지하고 실패 상태를 보고한다.

수용기준:

- 하나의 명령 또는 CI 작업으로 전체 산출물을 재생성한다.
- 같은 입력으로 같은 결과가 생성된다.
- 107개 지역의 `성공`, `무거래`, `오류` 상태 합계가 107이다.
- 이전 배포 대비 비정상 급증·급감과 누락을 검사한다.

### FR-RE-003 출처 매니페스트 — P0

요구사항:

- 지정 고시, 법령, 조세 특례, 거래 데이터마다 출처 URL, 문서 ID, 시행·기준일, 수집일, 유효기간, 확인 상태를 기록한다.
- 화면에 표시되는 설명과 수치가 매니페스트 항목을 참조한다.
- 유효기간 경과, 출처 접근 실패, 마지막 확인일 초과를 검출한다.
- 법령 조문을 장문 복제하지 않고 공식 원문으로 연결한다.

수용기준:

- 핵심 특례 카드마다 최소 하나의 활성 출처가 있다.
- 모든 거래 차트에 거래 기간과 수집일이 표시된다.
- 만료·재검토 필요 출처가 있으면 빌드 경고 또는 실패 정책에 따라 배포를 차단한다.

### FR-RE-004 데이터 검증과 배포 게이트 — P0

요구사항:

- JSON 스키마 검증, 지역 수, 지역 키 유일성, 숫자 범위, 월 연속성, 합계 일치 검사를 수행한다.
- 대표 거래가 해당 지역·기간 집계와 일치하는지 확인한다.
- 이전 버전과 비교해 변화가 큰 항목을 보고서로 남긴다.
- 필수 검사가 실패하면 배포하지 않는다.

수용기준:

- 테스트 실패 상태에서 GitHub Pages 산출물이 갱신되지 않는다.
- 검증 보고서에 실패 지역, 규칙, 실제 값이 표시된다.
- 데이터가 0인 것과 수집 실패를 구분한다.

### FR-RE-005 프런트엔드 구조 분리 — P0

요구사항:

- 단일 `index.html`에서 CSS, UI 로직, 데이터 로더를 분리한다.
- 원천·중간·배포 데이터의 디렉터리와 생성 규칙을 구분한다.
- 외부 프레임워크 도입 없이 정적 빌드를 우선 검토한다.
- 지역 상세 정적 생성에 필요한 최소 빌드 스크립트를 제공한다.

수용기준:

- 콘텐츠 수정이 거래 집계 로직을 변경하지 않는다.
- 데이터 갱신이 HTML 수작업 편집을 요구하지 않는다.
- 기존 홈 화면의 주요 기능에 대한 회귀 테스트가 있다.

### FR-RE-006 사이트 전체 최신성 표시 — P0

- 헤더 또는 주요 탐색 영역에 거래 데이터 기준기간과 사이트 마지막 갱신일을 표시한다.
- 정책 설명에는 마지막 법령 확인일을 표시한다.
- 오래된 데이터는 경고 배지를 표시하고 최신처럼 표현하지 않는다.
- `/sources/`에서 전체 데이터 이력을 확인할 수 있다.

### FR-RE-007 지역 검색·필터 — P1

요구사항:

- 지역명과 시도명으로 검색한다.
- 시도, 지정 유형, 최근 거래 여부, 거래량 구간으로 필터링한다.
- 지도, 지역 목록, 비교 선택 상태를 동기화한다.
- 모바일에서는 검색 결과 목록을 지도보다 먼저 사용할 수 있다.

수용기준:

- 사용자가 지역명을 입력해 두 번 이내 조작으로 상세에 도달한다.
- 필터 결과 수가 지도와 목록에서 일치한다.
- 결과가 없을 때 조건 초기화 안내를 제공한다.

### FR-RE-008 지역 상세 페이지 — P1

요구사항:

- 107개 지역마다 안정적인 `regionSlug`와 정적 URL을 제공한다.
- 지정 유형, 지정 근거, 적용 시점, 핵심 특례, 거래 요약, 월별 차트, 대표 거래, 표본 경고를 표시한다.
- 모든 수치에 기준기간과 표본 수를 표시한다.
- 해당 지역의 공개 PolicyMap이 검증된 경우에만 관련 현장지도 링크를 표시한다.

수용기준:

- 107개 URL이 빌드되고 내부 링크와 제목이 유효하다.
- 무거래 지역도 오류 페이지가 아니라 설명 가능한 상세 페이지를 가진다.
- 소셜·메신저 공유 시 지역명이 포함된 제목과 설명이 생성된다.

### FR-RE-009 지역 비교 — P1

요구사항:

- 최소 2개, 최대 3개 지역을 비교한다.
- 지정 유형, 최근 24개월 거래 건수, 거래 발생 월 수, 중위가격, ㎡당 중위가격, 최근 거래월을 표시한다.
- 동일 시도·지정 유형·거래 규모를 기준으로 비교 후보를 제안할 수 있다.
- 비교 상태를 URL 쿼리에 저장한다.

수용기준:

- 잘못된 지역 키나 4개 이상 선택은 안전하게 거부한다.
- 표본이 다른 지역의 가격만 단순 강조하지 않는다.
- 비교 URL을 다른 기기에서 열어 동일한 비교가 재현된다.

### FR-RE-010 거래 표본 해석 — P1

- `거래 없음`, `표본 매우 적음`, `표본 제한`, `일반` 등 품질 상태를 규칙 기반으로 표시한다.
- 규칙과 임계값을 코드와 방법론 문서에 공개한다.
- 표본이 적을수록 가격 변화율을 약하게 표현하거나 숨긴다.
- 평균 대신 중위값을 기본으로 하되 선택 이유를 설명한다.

### FR-RE-011 세컨드홈 확인 순서 — P2

요구사항:

- 기존 주택 수, 취득 지역, 취득 시점, 주택가액 등 확인 항목을 단계형으로 제공한다.
- 결과는 `대상 가능성 있음`, `추가 확인 필요`, `현재 안내 범위 밖` 수준으로 제한한다.
- 각 단계에 근거 조항, 시행일, 공식 문의처를 연결한다.
- 사용자의 답변을 서버에 저장하지 않는다.

수용기준:

- 결과 화면에 확정 세무판단이 아니라는 고지가 있다.
- 근거가 만료·재검토 상태면 체크리스트 결과 제공을 중단하고 공식 원문 확인으로 유도한다.

### FR-RE-012 정책 변화 타임라인 — P2

- 지역 지정, 관심지역 지정, 주요 특례 신설·변경·종료를 시간순으로 표시한다.
- 사건은 출처 매니페스트를 참조한다.
- 변경된 정책이 영향을 주는 지역과 기존 설명을 식별한다.
- 시행 전, 시행 중, 종료·재검토 상태를 구분한다.

### FR-RE-013 PolicyMap 연결 — P2

- 공개 상태이고 출처, 기준일, 관리 주체가 있는 지도만 연결한다.
- 지역 코드가 일치하는 지도를 지역 상세에서 보여준다.
- 시설 수치를 이 저장소에 복제하지 않고 원 PolicyMap 링크나 허용된 공개 API로 읽는다.
- 연결이 없을 때 빈 섹션을 노출하지 않는다.

### FR-RE-014 다운로드와 인용 — P2

- 필터·비교 결과를 CSV로 내려받는다.
- 지역 상세의 출처 목록과 기준일을 인용용 텍스트로 복사한다.
- 데이터 사전, 집계 방법, 이용조건을 `/sources/`에서 제공한다.
- 다운로드 파일에도 생성일과 출처 버전을 포함한다.

## 12. 비기능 요구사항

### 성능

- 홈은 전체 상세 데이터를 한 번에 내려받지 않는다.
- 검색에 필요한 지역 인덱스와 선택한 지역 데이터만 우선 로드한다.
- 모바일 저속 연결에서도 텍스트와 핵심 수치를 지도보다 먼저 표시한다.

### 접근성

- WCAG 2.2 AA를 목표로 한다.
- 지도 정보는 목록과 표로 동등하게 제공한다.
- 차트에는 텍스트 요약과 표 데이터를 제공한다.
- 색만으로 지정 유형이나 증감을 구분하지 않는다.

### 검색·공유

- 지역 상세마다 고유 제목, 설명, canonical URL을 제공한다.
- 정적 사이트맵에 107개 지역과 정책 페이지를 포함한다.
- 잘못된 지역 URL은 홈이 아니라 명확한 404와 검색 진입을 제공한다.

### 보안·프라이버시

- 사용자 답변과 검색어를 개인 식별정보와 결합해 저장하지 않는다.
- API 키와 원본 인증정보를 저장소나 클라이언트에 노출하지 않는다.
- 외부 링크는 안전한 새 창 정책을 적용한다.

### 법적·편집 안전

- 투자 권유가 아니라는 고지를 핵심 화면과 방법론에 표시한다.
- 세제·법령 설명에는 확인일과 공식 원문 링크를 제공한다.
- 정확한 적용은 취득 시점의 법령과 관계기관 확인이 필요함을 설명한다.

## 15. 핵심 수용 시나리오

### 시나리오 A — 거래가 있는 지역

1. 사용자가 해남군을 검색해 상세로 이동한다.
2. 지정 유형과 근거, 거래 기준기간, 거래 수, 중위값, 표본 상태를 확인한다.
3. 출처 링크를 열고 상세 URL을 공유한다.
4. 공유받은 사람도 동일한 지역과 기준일을 본다.

### 시나리오 B — 거래가 없는 지역

1. 사용자가 거래가 없는 대상 지역을 연다.
2. 화면은 0을 오류나 누락으로 오해하지 않도록 `해당 기간 확인된 거래 없음`으로 표시한다.
3. 지정 근거와 정책 정보는 정상 제공한다.
4. 데이터 수집 오류일 경우에는 무거래로 표시하지 않는다.

### 시나리오 C — 지역 비교

1. 사용자가 인구감소지역 2개와 관심지역 1개를 선택한다.
2. 지정 유형, 거래 표본, 가격 지표가 같은 단위와 기간으로 표시된다.
3. 표본이 적은 지역에는 강한 경고가 붙는다.
4. 비교 URL을 복사해 다시 열면 선택 상태가 복원된다.

### 시나리오 D — 법령·고시 변경

1. 출처 점검에서 유효기간 경과 또는 원문 변경을 감지한다.
2. 관련 정책 설명은 재검토 상태가 된다.
3. 검토 전까지 오래된 조건을 현재 유효한 사실처럼 표시하지 않는다.
4. 확인 후 매니페스트 버전과 마지막 검토일을 갱신한다.

## 18. 미결정 사항

1. 월별 갱신을 GitHub Actions에서 할지 별도 수집 환경에서 할지
2. 원본 거래 데이터를 저장소에 둘지 릴리스 자산·외부 저장소에 둘지
3. 지역 URL을 한글 슬러그로 할지 영문·코드 기반으로 할지
4. 비교 후보 추천 기준을 제품 규칙으로 고정할지 단순 필터로 시작할지

6. PolicyMap 연결 지도의 승인·검증 주체

## 19. 완료 정의

R1은 공식 원자료로 107개 지역의 최근 24개월 거래 산출물을 재현 가능하게 생성하고, 각 수치와 특례의 출처·기준일을 표시하며, 검증 실패 시 배포를 막을 수 있을 때 완료로 본다.
